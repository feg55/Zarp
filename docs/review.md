# Ревью Zarp — 25.09.2026

Проверена локальная копия `feg55/Zarp` на базе коммита `a70d082`: интерфейс WinForms, конфигурация, управление WARP/zapret2, автозапуск и публикация Windows EXE.

## Исправлено

- **Ложное предупреждение о VPN:** Teredo, ISATAP и 6to4 больше не считаются сторонними VPN. Неопределённые шлюзы `0.0.0.0` и `::` не учитываются, а поиск `tun`/`tap` не срабатывает на случайные части слов. Активные VPN со шлюзом по-прежнему определяются; состояние Up само по себе не доказывает, что через адаптер идёт весь трафик.
- **Закрытие окна:** добавлен диалог «Скрыть в трей / Закрыть приложение» с флажком «Запомнить мой выбор». Отмена и Escape сохраняют открытое окно. Однократный выбор не записывается в настройки. Старые настройки сохраняются; новый вопрос появляется, пока пользователь явно не запомнит действие.
- **Настройки:** доступны три варианта поведения при закрытии. Выбор сохраняется даже во время асинхронной проверки автозапуска — раньше общий `_loading` мог игнорировать изменения пользователя.
- **Завершение работы:** выход дожидается текущей операции и её очистки. Повторное закрытие не прерывает ожидание; новые подключения и применение обновлений после начала выхода запрещены. Пункт «Выход» из трея закрывает приложение независимо от сохранённого поведения крестика.
- **Подготовка подписи:** добавлены SignPath и проверка Authenticode/timestamp. Подписание опционально и включается через `SIGNPATH_ENABLED=true`; без него релиз публикуется с явной отметкой об отсутствии подписи. При включённой подписи её ошибка блокирует релиз. SHA-256 и attestation относятся к окончательному файлу. Секреты и сертификат ещё не подключены; предупреждение SmartScreen у текущего неподписанного EXE этим не устранено. См. [инструкцию](code-signing.md).
- **Единый стиль интерфейса:** системный ComboBox заменён тёмным списком на базе той же кнопки, что используется в приложении. Шестерёнка рисуется вектором по центру кнопки, без зависимости от шрифтового символа.

## Оставшиеся замечания

1. **P2 — ошибка определения владельца процесса.** В [Zapret.FindOurProcesses](../src/Zarp/Core/Zapret.cs) `path == null` считается подтверждением принадлежности процесса Zarp. При невозможности прочитать путь чужой `winws2` попадает в `Running` и список для `Stop()`, который пытается его завершить. Следует считать процесс своим только после совпадения полного пути либо по сохранённому идентификатору собственного процесса. Сценарий с чужим процессом на рабочей машине не запускался.
2. **P2 — ошибки warp-cli теряются.** В [Warp.SetTransportAsync](../src/Zarp/Core/Warp.cs) не проверяются результаты команд изменения протокола, а `_transport` обновляется даже при ненулевом коде возврата. Следующий вызов с тем же протоколом пропустит настройку; поиск может проверить стратегию на прежнем транспорте. Нужна проверка `RunResult.Ok` до обновления кеша и явное сообщение об ошибке.
3. **P2 — обновления zapret2 доверяют скачанным файлам без отдельной проверки происхождения.** [ExtractReleaseAsync](../src/Zarp/Core/Zapret.cs) получает ZIP по HTTPS и распаковывает исполняемые компоненты, а [fetch-zapret.ps1](../tools/fetch-zapret.ps1) берёт меняющийся `latest`. Подпись внешнего Zarp не удостоверяет будущие скачанные обновления. Стоит закреплять версию/контрольную сумму при сборке и проверять доступные upstream-подписи или attestation для обновлений. Сам по себе хеш, полученный вместе с архивом из того же скомпрометированного источника, недостаточен.

Эти замечания выявлены статическим анализом и остаются вне исправлений двух заявленных проблем.
